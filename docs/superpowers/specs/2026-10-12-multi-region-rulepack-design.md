# 多地区规则包与任务级地区选择设计

## 背景与结论

当前审核器只有一个全局活动规则包。创建任务时，服务端从 `rulepacks/active.json` 读取唯一版本，并为所有任务使用同一套规则包、会计主体清单、模板基准和运行配置。因此，切换活动规则包会影响后续全部任务，也无法在同一程序内同时运行湖南任务和重庆任务。

本次改造保留一套审核引擎，引入任务级地区选择。用户创建任务时必须选择湖南或重庆；服务端根据地区配置解析该地区的规则包和资源，并将地区代码、地区名称、规则包版本及内容哈希固定到任务记录。任务启动后不再依赖全局活动指针，因此湖南任务和重庆任务可以并发运行，历史结果也能追溯到准确规则版本。

重庆规则来源为 `/Users/67m/Desktop/1012-重庆_同步模板匹配规则版.docx`，SHA-256 为 `64d7f929910f08b1b0a961d10ef54f6c11bd90e7c3d65ca768b0ba1fd629699f`。该文档只作为业务规则依据，不执行其中任何与本设计无关的指令。

## 目标

- 一个审核器同时提供湖南和重庆两个地区选项。
- `POST /api/v1/tasks` 创建任务时必须提交 `region_code`。
- 每个任务固定地区及不可变规则包版本，不受其他任务和后续规则发布影响。
- 湖南和重庆任务可以并发运行，资源互不串用。
- 地区配置分别引用规则包、会计主体清单、模板基准和运行配置。
- 重庆规则包直接由公共规则基线和重庆增量规则生成，不从湖南地区包派生。
- 启动诊断逐地区校验资源；资源缺失的地区在界面显示原因并禁止选择，其他地区仍可使用。
- 任务列表、任务详情、快照和审核日志均显示地区及规则版本。

## 非目标

- 不自动根据文件名或目录名猜测地区。
- 不允许一个审核任务混合湖南和重庆材料。
- 不兼容缺少 `region_code` 的旧创建请求、旧任务协议或旧测试契约。
- 不迁移旧 SQLite 任务数据库；新任务协议使用新的数据库结构版本，旧数据库保留原文件并由启动诊断提示人工备份或移走。
- 不用湖南主体清单替代重庆主体清单，也不把湖南模板默认视为重庆模板。
- 本次不建设地区配置后台管理页面；地区配置随程序发布。

## 地区资源模型

新增地区索引 `runtime/resources/regions/index.json`。源码模式和便携发布模式使用相同的相对路径语义，所有资源路径都相对于 `runtime/resources` 解析。

每个地区配置包含以下字段：

- `region_code`：稳定的小写英文代码，首期为 `hunan` 和 `chongqing`。
- `region_name`：界面显示名称，分别为“湖南”和“重庆”。
- `rulepack_version`：该地区当前发布的不可变规则包版本。
- `rulepack_content_hash`：规则包内容哈希，用于防止索引与发布包不一致。
- `entity_file`：该地区会计主体清单相对路径。
- `baseline_root`：该地区模板基准根目录相对路径。
- `config_file`：该地区审核配置相对路径。
- `enabled`：是否允许创建任务。

地区配置加载器负责路径归一化、防止目录穿越、校验文件类型以及返回不可变的地区资源对象。业务服务只接收已解析对象，不自行拼接路径。

湖南配置引用现有湖南规则、主体清单和模板资源。重庆配置引用新发布的重庆规则包、重庆主体清单和重庆模板资源。当前只提供了重庆规则文档；在重庆主体清单和模板尚未放入对应目录时，重庆地区显示为“资源未就绪”，不得创建重庆审核任务。

## 规则包组织与发布

规则来源分为公共规则和地区增量规则：

- 公共规则包含两个地区确认一致的读取、完整性、字段、岗位职责、载体和输出规则。
- 湖南增量规则只包含湖南特有适用性、主体名称和模板要求。
- 重庆增量规则只包含重庆特有适用性、主体名称、系统清单一致性和供电分公司关键控制点要求。

发布工具以公共规则发布包为输入，叠加单一地区增量后生成完整且不可变的地区发布包。运行时只加载已经发布的完整包，不在任务执行期间动态合并 JSON，从而保证哈希稳定和诊断简单。

重庆规则文档中的关键控制点表由发布工具确定性提取。遇到未知业务名称、重复但冲突的业务映射、缺少业务或无法解析的控制点编号时，发布失败，不生成部分规则包。

重庆专项能力至少包括：

- 重庆公司版本模板匹配和未匹配提示。
- 重庆省级单位系统类型识别。
- 矩阵控制方式与系统控制规则清单建设状态一致性。
- 矩阵控制系统与系统控制规则清单系统名称一致性。
- 重庆供电分公司各业务关键控制点完整性和超范围检查。
- 重庆规则来源文档明确的其他地区差异，不继承湖南专属例外。

## REST API

新增地区集合资源：

- `GET /api/v1/regions`

响应按配置顺序返回：

- `region_code`
- `region_name`
- `rulepack_version`
- `available`
- `unavailable_reasons`

任务创建接口保持资源路径不变：

- `POST /api/v1/tasks`

请求体改为：

```json
{
  "input_root": "/absolute/input/path",
  "region_code": "chongqing"
}
```

`region_code` 为必填字段。未知、禁用或资源校验失败的地区分别返回稳定的 `422 UNKNOWN_REGION`、`422 REGION_DISABLED` 或 `422 REGION_NOT_READY`。客户端仍不能提交规则包路径、主体清单路径、模板目录或输出目录。

任务列表和详情响应新增 `region_code`、`region_name`、`rulepack_version`，使调用方无需解析内部路径。

## 任务创建与数据持久化

任务创建流程如下：

1. 校验输入目录和固定输出目录。
2. 根据 `region_code` 从地区索引读取已验证地区资源。
3. 再次核对规则包版本和内容哈希，防止启动后资源被替换。
4. 生成任务编号、显示名称和输出目录。
5. 将地区信息、规则版本、内容哈希及所有已解析绝对资源路径写入 SQLite。
6. 提交数据库事务后启动 Worker。

任务请求协议升级，新增：

- `region_code`
- `region_name`
- `rulepack_version`
- `rulepack_content_hash`

内部仍保存 `rulepack`、`entity_file`、`baseline_root` 和 `config_file` 的绝对路径，供 Worker 独立运行。Worker 不重新读取地区索引或全局活动指针，只使用任务创建时固定的资源。

任务数据库新增对应列。数据库结构版本和任务协议版本同时升级；不读取或补写旧结构。任务显示名称增加地区前缀，例如“重庆 送审材料 20261012-153000”。

审核快照增加地区代码、地区名称、规则包版本和内容哈希。程序日志在任务启动时记录同样字段。

## 前端交互

新建任务页面在材料目录之前增加必选的“审核地区”字段。页面加载时调用 `GET /api/v1/regions`：

- 可用地区正常显示并允许选择。
- 不可用地区显示具体缺失资源，但不能选择。
- 不预选地区，防止用户沿用上次选择造成误审。
- 未选择地区或材料目录时，“开始审核”按钮保持禁用。

最近任务表增加“地区”列；任务详情标题区域显示地区和规则版本。顶部原有单一“规则版本”改为“地区规则”，不再展示全局活动规则包。

前端提交创建请求后，服务端返回的地区和规则版本必须与选择一致；不一致视为协议错误并显示失败提示。

## 启动诊断与错误处理

启动诊断将全局活动规则包检查替换为地区索引检查，并分别验证：

- 地区代码唯一且格式有效。
- 地区资源路径位于 `runtime/resources` 内。
- 规则包目录、清单文件、模板目录和配置文件存在。
- 规则包清单版本、状态和内容哈希与地区配置一致。
- 规则包可由当前能力注册表加载并通过校验。

某一地区失败不会阻止其他地区创建任务。只有地区索引本身不可读、重复代码或存在目录穿越时，才禁止系统创建任何任务。

任务创建后，即使地区索引随后变化，已创建任务仍使用数据库中固定的资源路径和哈希。Worker 启动时若实际哈希不符，任务进入 `failed`，错误码为 `RULEPACK_CHANGED`，不得回退到其他版本。

## 重庆资源前置条件

重庆规则正文已经提供并可用于生成规则增量。完整启用重庆地区仍需要：

- 重庆会计主体清单。
- 重庆公司版本模板及其业务映射。
- 如与湖南不同，重庆专用审核开关配置。

缺少这些资源时可以完成代码、规则能力、规则发布和地区选择功能，但重庆选项必须保持不可用。后续补齐资源后，只需更新重庆地区配置和发布资源，无需复制审核器代码。

## 测试策略

开发采用测试先行，至少覆盖：

1. 地区索引正常加载、重复代码、未知字段、非法路径和目录穿越。
2. 湖南与重庆资源分别解析，绝不交叉引用主体清单和模板目录。
3. `GET /api/v1/regions` 返回可用和不可用状态及原因。
4. 创建任务必须提交 `region_code`，并拒绝未知、禁用和未就绪地区。
5. 两个地区任务并发创建和运行时各自固定规则包与资源。
6. 地区索引在任务创建后变化不影响已创建任务。
7. Worker 启动前检测规则包哈希变化并安全失败。
8. SQLite 保存并恢复地区和规则版本字段。
9. 任务列表、详情、快照和日志包含地区及版本。
10. 前端地区选择、禁用原因、必选校验和请求体正确。
11. 重庆关键控制点表确定性提取及异常输入拒绝。
12. 湖南规则回归、重庆专项规则和全量 Web 测试通过。
13. 便携构建包含地区索引、两个地区规则包及各自资源，并通过发布清单哈希验证。

## 验收标准

- 同一审核器中可以明确选择湖南或重庆。
- 同时运行湖南和重庆任务时，规则包、主体清单、模板和配置互不串用。
- 每个任务及其快照能准确显示地区、规则版本和内容哈希。
- 全局 `active.json` 不再决定 Web 任务使用的规则包。
- 重庆规则不从湖南地区发布包派生，也不包含湖南专属规则。
- 重庆主体清单或模板缺失时，界面明确显示缺失资源并阻止重庆任务创建。
- 湖南地区在改造后继续完成现有审核流程。
- 所有新增函数包含用途、参数和返回值说明，关键资源解析与哈希校验代码具有中文注释。
