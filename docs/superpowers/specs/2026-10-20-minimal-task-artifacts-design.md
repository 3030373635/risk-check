# Web 审核任务汇总性能与最小产物设计

## 背景

任务 `20261020-102012-8839` 共生成 211,601 条审核意见。29 个业务审核在约 5 分钟内完成，但任务随后在 99% 的“生成汇总结果”阶段继续运行约 15 分 47 秒。

本次任务归档中的 `.task` 未压缩体积约 277.5 MB，其中主要文件为：

- `findings.json`：约 170.1 MB。
- `_risk_audit/review_tasks.json`：约 67.1 MB。
- `_risk_audit/ownership.json`：约 26.1 MB。
- `_risk_audit/复核事项.csv`：约 12.2 MB。

当前统计报告存在两项主要性能问题：

1. Excel 与 HTML 报告分别执行一次完整统计归集，相同数据被重复处理。
2. 意见只按文本建立候选列表，再按文件、工作表和行号线性查找；高频意见拥有数万条同文本候选，导致大规模重复扫描。

用户已确认 Web 审核任务完成后只需要保留审核后的 Excel、统计报告、日志、未审核文件和未完成项，不需要保留逐条结构化意见、写回归属、集中复核明细或实体级中间报告。

## 目标

1. Web 审核任务的统计归集只执行一次，并由同一份归集结果生成 Excel 和 HTML。
2. 将意见与写回位置的匹配改为直接索引，避免按高频意见文本反复线性扫描。
3. Web 任务不生成或不持久保留无用户需求的大型内部报告。
4. 任务终态只保留以下内容：
   - 输出目录中的审核后业务 Excel。
   - 输出目录根部的 `审核统计表.xlsx` 和 `审核统计表.html`。
   - `.task/worker.log`。
   - `.task/report/audit.log`。
   - `.task/report/_risk_audit/未审核文件.json`。
   - `.task/report/_risk_audit/未完成项.json`。
5. SQLite 继续保存任务状态、数量摘要和保留文件路径，前端现有任务详情与结果打开能力不变。
6. 对与本次任务规模相当的数据，将 `.task` 终态体积控制在 5 MB 以内，并将 99% 汇总阶段控制在 2 分钟以内。

## 非目标

1. 不迁移或压缩历史任务中的旧 `.task` 目录。
2. 不兼容依赖旧详细报告目录结构的代码、旧测试或外部脚本。
3. 不为前端新增逐条意见浏览、集中复核明细或历史任务差异对比功能。
4. 不改变任务 REST API 路径、任务状态集合或输出业务 Excel 的目录结构。
5. 不改变规则判断和审核意见写回结果。

## 方案选择

采用“Web 最小产物策略 + 单次统计归集 + 精确位置索引”。

不采用以下方案：

- 只压缩大型 JSON：能够降低归档体积，但仍会生成并重复处理全部数据，不能解决 99% 阶段耗时。
- 任务完成后再删除全部详细产物：能够降低终态占用，但生成大型 `findings.json`、`review_tasks.json` 和复核 CSV 的时间与 I/O 仍然存在。
- 将逐条意见写入 SQLite：会扩大任务数据库、增加迁移和查询复杂度，而当前前端不需要这些数据。

## 运行模式与产物策略

审核核心增加显式产物策略，不通过零散布尔参数控制文件。

### Web 最小产物策略

Web Worker 固定使用最小产物策略。该策略要求：

- 内存中的 `findings`、`ownership`、`statuses` 等数据仍可用于本次规则执行、Excel 写回和最终统计。
- 不写出 `findings.json`、`statuses.json`、`inventory.json`、`review_tasks.json`、`复核事项.csv`、责任模式明细和实体/业务级结果目录。
- 不调用仅服务于被删除产物的构建步骤，例如 `build_review_tasks` 和详细责任模式报告生成。
- 必须写出审计日志、未审核文件和未完成项。
- 统计报告成功生成后，释放统计索引和大型集合引用，再进入最终摘要和状态发布。

### CLI 详细产物策略

普通 CLI 若仍需要运行差异比较或开发诊断，可显式使用详细产物策略。详细策略不属于 Web `.task` 的默认路径，也不得影响 Web 最小策略的性能。

产物策略使用统一枚举或不可变配置对象表达，变量命名统一使用 `artifact_policy`，不得同时出现 `minimal_report`、`keep_details` 等同义参数。

## 统计归集数据流

现有流程为：

```text
findings + ownership
  -> 完整归集 -> Excel
  -> 完整归集 -> HTML
```

改造后流程为：

```text
findings + ownership
  -> 构建位置索引
  -> 单次归集为 AuditStatisticsData
       ├─> Excel 渲染
       └─> HTML 渲染
```

新增不可变统计数据对象 `AuditStatisticsData`，只包含渲染所需的主体、业务和已归并意见，不携带完整 `Finding` 对象。Excel 和 HTML 写入函数只接收该对象和输出路径，禁止自行重新归集。

建议接口：

```python
def collect_audit_statistics(...) -> AuditStatisticsData:
    """归集一次审核统计；参数为审核文件、写回归属和结构化意见。"""


def write_audit_statistics(path: Path, statistics: AuditStatisticsData) -> None:
    """写入 Excel 统计表；path 为输出路径，statistics 为已归集数据。"""


def write_audit_statistics_html(path: Path, statistics: AuditStatisticsData) -> None:
    """写入 HTML 统计表；path 为输出路径，statistics 为已归集数据。"""
```

所有新增或修改函数必须具有中文注释及参数解释；索引建立、终态清理和结果路径更新等重要代码行必须增加中文注释。

## 意见位置索引

归集前一次遍历 `findings`，建立以下索引：

- 精确位置索引：`(message, file_path, sheet, row) -> Finding`。
- 资料级回退索引：`(message, entity_code) -> Finding`。
- 业务文件索引：按主体、业务、版本和相对路径直接定位文件。

归集每个 ownership 意见时，先解析一次单元格行号，然后执行常数时间索引查询。不得遍历同文本下的全部候选意见。

若同一精确位置出现多个 Finding，索引构建阶段必须验证它们的统计路由信息一致；不一致时记录明确错误并终止统计生成，不能静默选择任意一条。

统计复杂度目标为 `O(F + O)`：`F` 为 Finding 数量，`O` 为 ownership 中拆分后的意见数量。文件数量和业务数量只参与常数级索引查找，不再嵌套扫描。

## 最小目录结构

Web 任务进入终态后，允许保留的隐藏目录结构如下：

```text
<output-root>/
  审核统计表.xlsx
  审核统计表.html
  <审核后的业务文件...>
  .task/
    worker.log
    report/
      audit.log
      _risk_audit/
        未审核文件.json
        未完成项.json
```

空的 `未审核文件.json` 和 `未完成项.json` 仍写为 `[]`，保证数据库结果路径稳定。除上述白名单外，Web 最小策略不得在 `.task` 留下其他文件或空目录。

## 终态清理

最小策略优先从源头跳过非必要文件生成。对于审核过程中必须临时落盘的 ownership 或增量结果，统一写入 Worker 的系统临时目录，不写入最终 `.task`；任务结束时由现有运行时清理流程删除。

增加幂等的 `compact_task_artifacts` 函数，按固定白名单清理 `.task`：

1. 解析并验证任务输出根目录。
2. 确认目标位于该输出根的 `.task` 内。
3. 保留白名单文件，删除其他普通文件和目录。
4. 不跟随符号链接或 Windows 重解析点。
5. 清理失败时追加 `cleanup_warning` 任务事件，但不得把已成功审核的任务改为失败。

Worker 在完成、部分完成、失败和安全取消的 `finally` 阶段调用该函数。大型运行期数据只允许位于任务系统临时目录；Worker 被强制结束或系统掉电时，现有任务运行时恢复与清理流程负责删除该临时目录，不需要扩展任务数据库结构。

历史任务不自动清理。最小产物策略只作用于改造后启动的 Web Worker，不扫描或修改既有输出目录。

## 状态发布顺序

完成或部分完成任务按以下顺序发布：

1. 完成全部业务文件写回。
2. 单次归集统计数据。
3. 依次原子写入 Excel 和 HTML 统计报告。
4. 写入未审核文件和未完成项。
5. 执行 `.task` 白名单清理。
6. 验证全部保留文件存在且可读。
7. 向 SQLite 写入结果摘要和 100% 终态。

统计报告任一格式生成失败时，不得发布完成状态。已生成的另一格式可以保留，任务按现有失败或部分完成规则记录明确错误。

任务结果摘要只保存仍存在的路径。被移除的 `run_dir`、详细 Finding 或内部报告路径不得继续出现在 `result_summary_json` 中。

## REST API 与前端

保持以下接口不变：

- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{task_id}`
- `POST /api/v1/tasks/{task_id}/output-openings`
- `POST /api/v1/tasks/{task_id}/report-openings`
- `GET /api/v1/tasks/{task_id}/unaudited-files`
- `GET /api/v1/tasks/{task_id}/incomplete-items`

任务详情仍显示意见数量、告警数量、未完成数量和进度。打开输出目录、Excel/HTML 统计报告、读取未审核文件与未完成项的行为保持不变。

前端不展示已删除的内部报告，不新增兼容入口。

## 错误处理

- 索引冲突：统计生成失败，日志记录冲突键和涉及规则，不输出不可信统计。
- Excel 生成失败：删除不完整临时文件，不进入 100%。
- HTML 生成失败：删除不完整临时文件，不进入 100%。
- 最小报告写入失败：任务按现有规则进入失败或部分完成，日志路径必须保留。
- 清理失败：任务结果仍可交付，追加清理警告事件并保留未能删除的文件。
- 保留文件校验失败：禁止发布完成状态，返回稳定错误码。

## 测试策略

### 统计性能与正确性

1. 同一批数据只调用一次 `collect_audit_statistics`，Excel 和 HTML 使用相同对象。
2. 高频相同意见下按文件、工作表和行号准确匹配 Finding。
3. 精确索引冲突时明确失败。
4. 资料级意见仍能按真实业务归组。
5. Excel 与 HTML 的主体、业务和意见计数一致。
6. 构造 20 万条 Finding 的性能测试，防止恢复为候选列表线性扫描。

### 最小产物

1. Web Worker 固定传入最小产物策略。
2. 最小策略不调用 `build_review_tasks`，不生成详细复核和逐条意见文件。
3. 任务成功、部分完成、失败和取消后，`.task` 只包含白名单文件。
4. 空的未审核文件和未完成项报告仍可由 API 读取。
5. `result_summary_json` 不包含已删除文件路径。
6. 清理函数拒绝输出根外路径、符号链接和重解析点。
7. 清理重复执行结果一致。
8. 清理失败只记录警告，不覆盖审核终态。

### 回归测试

运行统计报告、Web Worker、任务 API、任务恢复、任务删除、增量输出和完整规则测试。旧详细产物断言直接改为最小产物断言，不保留旧目录兼容分支。

## 验收标准

1. 与本次任务规模相当的数据中，`.task` 终态体积不超过 5 MB。
2. 同规模任务的 99% 汇总阶段不超过 2 分钟。
3. 统计归集在单次任务中只执行一次。
4. 统计匹配不存在按同文本候选列表逐条扫描的实现。
5. Web `.task` 中不存在 `findings.json`、`review_tasks.json`、`ownership.json`、`复核事项.csv` 或 `entities` 目录。
6. 审核后的业务 Excel、两种统计报告、日志、未审核文件和未完成项均可正常打开或读取。
7. 任务列表、任务详情、结果打开和删除接口通过回归测试。
8. 新增和修改函数命名统一，具有中文函数注释、参数解释和关键代码注释。
