# 风控矩阵审核器 Windows 便携桌面端与并行任务中心设计

## 1. 文档信息

- 设计日期：2026-09-24
- 目标平台：Windows 10/11 x64
- 交付方式：免安装 ZIP，解压后双击主程序运行
- 运行模式：完全离线
- 桌面框架：PySide6 + Qt Widgets
- 审核核心：现有 `risk_audit` Python 包
- 文档状态：用户已确认，可进入实施计划

本文档取代 `2026-09-23-windows-desktop-portable-design.md` 及其实施计划中的桌面架构结论。旧文档采用 QML、单任务和 `%LOCALAPPDATA%` 历史记录，与本次确认的 Qt Widgets、并行任务、便携目录及输出命名规则不一致，不得继续作为实施依据。

## 2. 背景与目标

现有程序是成熟的离线 Python 审核工具，已经具备 Excel、Word、PDF 和 WPS ET 材料读取、规则审核、审核副本写回、日志、规则包、本地模型及 LibreOffice 转换能力。桌面化不重写审核核心，只增加适合非技术用户使用的 Windows 图形界面、任务管理和便携交付能力。

成功标准：

1. 用户电脑不需要预装 Python、Qt 或 LibreOffice。
2. 用户不需要管理员权限，不运行安装程序，不配置环境变量。
3. 用户解压完整目录后双击 `风控矩阵审核器.exe` 即可使用。
4. 一次审核对应一个任务，多个任务能够同时运行并分别查看进度。
5. 每个任务的输出、LibreOffice profile、临时目录和日志相互隔离。
6. 主界面保持响应，单个任务异常不影响其他任务和桌面界面。
7. 原始材料保持只读，所有正式结果写入独立输出目录。
8. 界面关闭时避免误停任务，并能从系统托盘恢复。

## 4. 交付目录

交付包采用一个主程序加外部运行资源的混合便携结构：

```text
风控矩阵审核器-v2.0.0/
├── 风控矩阵审核器.exe
├── runtime/
│   ├── libreoffice/
│   │   └── program/
│   │       └── soffice.exe
│   ├── resources/
│   │   ├── rulepacks/
│   │   ├── baselines/
│   │   ├── entities/
│   │   └── models/
│   ├── licenses/
│   └── manifest.json
├── data/                         # 首次启动后生成
│   └── tasks.json
└── outputs/                      # 首次创建任务后生成
```

约束：

- Python、PySide6、桌面代码和普通 Python 依赖打入主程序。
- LibreOffice 作为稳定外部运行时保留，不在每次启动时释放到临时目录。
- 规则、基准、主体资源和本地模型放在 `runtime/resources`，便于校验和整体替换。
- `manifest.json` 记录资源版本、相对路径、大小和 SHA-256。
- 用户必须整体移动或复制交付目录，不能只复制主程序。
- 程序根目录始终使用 `Path(sys.executable).resolve().parent` 确定，不依赖进程当前工作目录。
- 启动时资源不完整则拒绝创建任务，并显示明确缺失项。
- 交付包必须包含 LibreOffice、Qt、Python 及其他第三方组件所要求的许可证和声明。

## 5. 输出目录规则

默认输出根目录是主程序所在目录下的 `outputs`。任务目录名由待审核材料目录的文件夹名和任务创建时间组成，任务名称不参与目录命名。

规则表达式：

```text
outputs/<材料目录名>-$(date +%Y%m%d-%H%M%S)
```

示例：

```text
材料目录：D:/报送材料/第一批资料0924
输出目录：outputs/第一批资料0924-20260924-103015
```

实现约束：

- `$(date +%Y%m%d-%H%M%S)` 表示命名格式，不调用 shell。
- 程序使用本机时间在创建任务时生成一次 `YYYYMMDD-HHMMSS`。
- `xxxxx` 取材料目录最后一级名称，即 `input_root.name`。
- Windows 不允许的文件名字符替换为 `_`，保留中文、空格和合法标点。
- 清理结尾空格和句点；处理后为空时使用 `审核任务`。
- 若同名目录已经存在，则追加递增序号，如 `-2`，不得覆盖已有结果。
- 输出目录不能与输入目录相同、包含输入目录或位于输入目录内部。
- 用户修改输出目录时仍执行可写性、重叠和冲突检查。

每个输出目录包含业务结果和内部任务状态：

```text
outputs/第一批资料0924-20260924-103015/
├── 审核统计表.xlsx
├── entities/
├── 其他审核结果文件
└── _task/
    ├── request.json
    ├── state.json
    ├── events.jsonl
    ├── worker.log
    ├── cancel.requested           # 仅取消时短暂存在
    ├── work/                      # 任务临时目录，结束后清理
    └── libreoffice-profile/       # 任务独立 profile，结束后清理
```

## 6. 界面设计

界面采用 Qt Widgets，实现接近 Windows 11 的简洁浅色/深色自适应风格。首要目标是让非技术用户明确知道“新建任务、看进度、开结果”，不设计复杂仪表盘。

### 6.1 主导航

- 审核任务
- 新建任务
- 使用帮助

左下角显示环境状态和当前运行任务数，例如“2 个任务并行运行”。

### 6.2 审核任务页

列表字段：

- 任务名称和任务编号
- 创建时间
- 状态
- 进度
- 查看、结果或重试操作

任务状态包括：

- `running`：正在运行
- `cancelling`：正在安全停止
- `completed`：完整完成
- `partial`：生成了结果但存在未完成检查
- `failed`：任务失败
- `cancelled`：用户取消
- `interrupted`：进程或电脑异常中断

### 6.3 新建任务页

字段和行为：

- 任务名称：默认使用材料目录名，可修改，只影响任务列表展示。
- 待审核材料目录：必填。
- 输出目录：自动按第 5 节规则生成，允许修改。
- 运行前检查：LibreOffice、规则版本、本地模型和资源完整性。
- 主操作：“创建并开始审核”。

创建成功后任务立即独立运行，不阻塞已存在的任务。

### 6.4 任务详情页

展示：

- 任务状态和总体进度。
- 已完成工作单元数和总工作单元数。
- 当前阶段、主体、业务和文件。
- 扫描、主体与范围校验、规则执行、结果生成四个阶段状态。
- 材料目录、输出目录、规则版本和已运行时间。
- 停止任务和打开任务目录操作。

材料扫描完成前使用不确定进度；扫描完成后以可执行工作单元的完成数量计算百分比，不使用虚构的时间进度。

### 6.5 结果状态

任务完成后显示：

- 处理文件数。
- 审核意见数。
- 待人工复核事项数。
- 失败或未完成项数。
- 打开结果目录、审核统计表和集中复核事项入口。

## 7. 技术架构

### 7.1 技术选型

- 桌面框架：PySide6。
- 界面层：Qt Widgets，不使用 QML。
- 审核核心：现有 `risk_audit` 包。
- 打包：PyInstaller 单主程序模式；LibreOffice 和业务资源作为外部目录随 ZIP 交付。
- 工作进程：同一主程序的 `--worker <request.json>` 模式。
- 状态交换：任务目录中的原子 JSON 状态文件和追加式 JSON Lines 事件文件。
- 任务索引：`data/tasks.json`，只保存任务元数据和结果路径，不保存材料内容。

### 7.2 模块边界

```text
risk_audit_desktop/
├── app.py                 # GUI 与 --worker 统一入口
├── main_window.py         # 主窗口、导航和托盘
├── task_list_page.py      # 任务列表
├── task_create_page.py    # 新建任务
├── task_detail_page.py    # 任务进度和结果
├── task_manager.py        # 并行工作进程生命周期
├── task_store.py          # tasks.json 和任务状态读写
├── task_paths.py          # 输出命名和目录隔离
├── task_contracts.py      # 请求、状态和事件模型
├── diagnostics.py         # 运行环境和资源校验
├── tray.py                # 托盘行为和通知
└── platform_windows.py    # Windows 文件、进程和单实例适配
```

所有模块使用明确边界：界面不得直接执行审核，Worker 不得依赖界面对象，审核核心不得反向依赖桌面包。

新增函数必须包含用途、参数及返回值注释。关键的进程管理、原子写入、路径保护和 LibreOffice 隔离代码必须添加中文注释。Python 变量统一使用清晰的 `snake_case`。

### 7.3 并行进程模型

```text
PySide6 主界面进程
├── Worker 任务 A ── risk_audit ── LibreOffice profile A
├── Worker 任务 B ── risk_audit ── LibreOffice profile B
└── Worker 任务 C ── risk_audit ── LibreOffice profile C
```

- 每次创建任务都立即启动独立 Worker，不设置应用级并发队列。
- Worker 在导入 PySide6 界面模块前识别 `--worker` 参数，避免加载无关界面资源。
- 每个 Worker 只读自己的请求文件，只写自己的任务目录。
- Worker 使用独立 LibreOffice profile、临时目录、运行目录和日志。
- Worker 通过参数列表启动 LibreOffice，不拼接 shell 命令。
- 单个 Worker 崩溃不结束主界面或其他 Worker。
- 主界面采用单实例机制；托盘程序已运行时再次双击 EXE，只激活原窗口。

### 7.4 状态和进度协议

`state.json` 采用写临时文件后原子替换的方式更新，避免界面读到半个 JSON。核心字段至少包括：

```json
{
  "schema_version": "1.0",
  "task_id": "20260924-103015-a1b2",
  "status": "running",
  "stage": "audit",
  "completed_units": 17,
  "total_units": 25,
  "progress_percent": 68,
  "current_entity": "示例单位",
  "current_business": "设备（资产）管理",
  "current_file": "岗位内控责任清单.xlsx",
  "worker_pid": 12345,
  "started_at": "2026-09-24T10:30:15+08:00",
  "heartbeat_at": "2026-09-24T10:33:57+08:00",
  "message": "正在执行审核规则"
}
```

`events.jsonl` 追加关键状态变化，用于诊断，不作为界面唯一状态来源。主界面定时读取各任务 `state.json`，刷新任务列表和详情页。刷新失败只影响对应任务显示，不影响其他任务。

审核核心通过可选进度回调报告阶段和工作单元。未传回调时现有命令行行为保持不变；不为旧的桌面事件协议提供兼容层。

### 7.5 任务索引与恢复

`data/tasks.json` 保存：

- 任务编号和展示名称。
- 输入目录和输出目录。
- 创建时间。
- 对应 `_task/state.json` 路径。

写入采用临时文件加原子替换。程序启动时：

1. 加载任务索引。
2. 读取每个任务状态文件。
3. 对标记为 `running` 的任务检查进程和心跳。
4. Worker 存在则重新关联显示。
5. Worker 不存在且心跳超时则标记为 `interrupted`。
6. 输出目录被移动或删除时保留任务记录，并显示“结果路径不存在”。

损坏的单条任务记录不得导致应用无法启动。

## 8. 任务停止和程序关闭

### 8.1 安全停止任务

用户点击“停止任务”后：

1. 界面二次确认。
2. 创建 `_task/cancel.requested`。
3. 任务状态变为 `cancelling`。
4. Worker 在当前安全工作单元结束后读取标记并停止。
5. 已完整生成的输出保留，任务标记为 `cancelled`，不能显示为成功。

若 Worker 长时间没有响应，界面可以提供“强制结束”二级操作，并明确提示可能留下未完成文件。

### 8.2 关闭窗口

有任务运行时点击右上角关闭按钮，显示三个选项：

1. “最小化到托盘并继续运行（推荐）”——默认主操作。
2. “停止全部任务并退出”——为所有任务发出安全停止请求，等待退出后关闭程序。
3. “取消”——返回主窗口。

托盘行为：

- 托盘提示当前运行任务数量。
- 双击托盘图标恢复主窗口。
- 所有任务完成后发送系统通知。
- 没有运行任务时关闭窗口直接退出。
- 不创建 Windows 服务；用户明确退出程序时所有 Worker 必须停止。

## 9. LibreOffice 隔离

- 固定调用 `runtime/libreoffice/program/soffice.exe`。
- 不搜索或使用用户电脑中已安装的 LibreOffice。
- 每个任务使用 `_task/libreoffice-profile` 作为唯一 profile。
- 保留现有禁用宏、活动内容和外部链接更新配置。
- 任务结束后清理 profile 和临时转换文件，保留任务状态及日志。
- 清理失败记录警告，但不能把已完成任务改为失败。
- 多任务测试必须证明不同 Worker 不共享 profile、临时文件和输出目录。

## 10. 错误处理

### 10.1 创建任务前阻止

- 输入目录不存在或没有可审核材料。
- 输出上级目录不可写。
- 输入输出目录重叠。
- 输出目录已经存在且会造成覆盖。
- LibreOffice 或业务资源缺失、版本不匹配或哈希校验失败。

界面提示必须包含具体路径、原因和下一步操作，不显示 Python 堆栈。

### 10.2 任务运行错误

- 单文件或单业务错误按现有审核核心策略记录，已完成输出继续保留。
- 致命异常只将对应任务标记为 `failed`。
- 完整堆栈写入 `_task/worker.log`。
- 界面显示简短错误说明、错误编号和“打开任务目录”入口。
- Worker 意外结束且没有终态时，主界面标记任务为 `interrupted`。

### 10.3 并行隔离错误

- 一个任务的取消、失败或 LibreOffice 崩溃不得修改其他任务状态。
- 任务不得写入其他任务的输出、profile、临时目录或日志。
- 主界面读取一个损坏状态文件时，其他任务继续正常刷新。

## 11. 安全与隐私

- 程序不建立网络连接。
- 原始材料不上传、不写入任务索引或诊断报告。
- 输入材料始终只读。
- 任务请求通过 JSON 文件和参数列表传递，不拼接 shell 命令。
- 输出目录名中的材料目录名称必须做 Windows 文件名清理。
- LibreOffice 使用隔离 profile，并禁用宏、活动内容和外链更新。
- 资源通过 `manifest.json` 和 SHA-256 校验完整性。
- 正式广泛分发前建议签名主程序，降低 SmartScreen 提示概率。

## 13. 测试与验收

### 13.1 自动化测试

- 输出目录名使用材料目录名和创建时间，不使用任务展示名称。
- 中文、空格、非法字符和结尾句点的目录名称清理正确。
- 同秒同名冲突不会覆盖旧目录。
- 输入输出目录重叠时拒绝创建任务。
- `state.json` 原子写入，损坏状态不影响其他任务。
- 同时启动至少两个 Worker，二者并行进入运行状态。
- 每个 Worker 使用不同 LibreOffice profile、临时目录和日志。
- 取消一个任务不影响另一个任务。
- 单个 Worker 异常只影响对应任务。
- 应用重启能够恢复已完成、运行中和中断任务状态。
- 有运行任务时关闭窗口显示正确选项。
- 无任务时关闭窗口直接退出。
- 第二次启动程序只激活现有单实例。
- 资源缺失和哈希错误在创建任务前被拦截。
- 保持现有审核核心测试通过。

### 13.2 Windows 实机验收

至少在一台未安装 Python 和 LibreOffice 的 Windows 10/11 x64 机器验证：

1. ZIP 解压后双击启动。
2. 中文和空格路径可正常选择及审核。
3. `.xlsx`、真实 `.xls`、可支持的 `.et`、`.docx`、`.doc` 和 PDF 材料行为符合现有边界。
4. 同时运行两个包含 LibreOffice 转换的真实任务。
5. 分别查看两个任务的实时进度。
6. 取消其中一个任务，另一个任务继续完成。
7. 最小化到托盘后任务继续运行并在完成时通知。
8. 异常关闭后重新启动，任务状态能够正确恢复或标记中断。
9. 输出位于 `outputs/<材料目录名>-YYYYMMDD-HHMMSS`。
