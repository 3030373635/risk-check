# 风控矩阵审核器单机离线 Web 版设计

## 1. 文档信息

- 设计日期：2026-09-25
- 目标平台：Windows 10/11 x64
- 产品形态：单机、完全离线、本地 Web 应用
- 交付方式：免安装 ZIP，解压后双击主程序运行
- 后端：Python、FastAPI、Uvicorn
- 前端：HTML5、CSS、原生 JavaScript、Bootstrap 5.3.8、Bootstrap Icons 1.13.1
- 审核核心：现有 `risk_audit` Python 包
- 文档状态：设计已在对话中确认，待用户审核本文档

本文档取代 `2026-09-24-windows-desktop-task-center-design.md` 及相关桌面端实施计划中的 GUI 架构结论。新版本不兼容或保留 PySide6 桌面界面，只复用与界面无关的任务、Worker 和审核核心能力。

## 2. 背景与目标

现有 Windows 便携版采用 PySide6 和 Qt Widgets。审核核心、任务持久化、独立 Worker、并行运行、资源检查和结果输出已经具备稳定边界，但桌面界面增加了 Qt 打包、窗口生命周期、主题和控件维护成本。

本次调整将界面替换为由本机 HTTP 服务提供的 Web 页面。用户仍然通过双击 EXE 启动程序，页面自动在默认浏览器中打开；浏览器只承担展示和交互，不上传材料，也不承载审核任务。审核材料、任务状态和结果始终保存在本机。

成功标准：

1. 用户电脑不需要预装 Python、Node.js、Web 服务、Qt 或 LibreOffice。
2. 用户解压完整 ZIP 后双击 `风控矩阵审核器.exe` 即可打开页面。
3. 程序不访问互联网，也不允许局域网设备访问。
4. 用户可通过 Windows 原生目录选择框选择任意本机材料目录。
5. 输出固定写入程序目录下的 `outputs`，用户不选择输出位置。
6. 浏览器关闭后，后端和正在运行的审核任务继续工作。
7. 再次双击 EXE 时不创建第二个服务实例，而是重新打开当前页面。
8. 多个审核任务可并行运行，单个任务异常不影响其他任务和本地服务。
9. 所有前端资源和第三方依赖随便携包交付，运行时不使用 CDN。
10. 界面达到已确认原型的清晰度和视觉质量，并支持系统深浅色模式。

## 3. 产品范围

### 3.1 第一版包含

- 本机 Web 服务和浏览器页面。
- 审核任务列表、新建任务、任务详情和使用帮助。
- Windows 原生输入目录选择。
- 自动生成且不可修改的任务输出目录。
- 运行环境和资源完整性检查。
- 多任务并行运行。
- 真实扫描与审核进度展示。
- 安全停止和经用户二次确认后的强制停止。
- 完成、部分完成、失败、取消和意外中断状态。
- 打开输出目录、统计表和集中复核结果。
- 浏览器关闭后的后台运行。
- 重复双击后的现有页面重开。
- 深浅色自适应。
- 无运行任务时直接退出，以及全部安全停止后退出。

### 3.2 第一版不包含

- 云端部署、局域网访问或多人协作。
- 用户账号、登录、角色和权限。
- 文件上传、网络同步、在线推理或自动联网更新。
- WebSocket、SSE 或服务端推送。
- Node.js、npm、Vite、React 或 Vue 运行环境与构建流程。
- 系统托盘。
- 安装程序、Windows 服务或管理员权限操作。
- 规则可视化编辑器。
- 任务断点续跑；中断任务只能重新创建。
- 旧 PySide6 界面和旧桌面入口兼容。

## 4. 总体架构

```text
风控矩阵审核器.exe
       │
       ├── Windows 单实例控制
       ├── 本机 HTTP 服务（127.0.0.1 + 随机端口）
       ├── 本次启动访问令牌
       └── 默认浏览器
               │
               ▼
        HTML/CSS/JavaScript
               │
          REST API / JSON
               │
               ▼
        Web 应用服务层
          │           │
          ▼           ▼
      TaskStore    TaskManager
          │           │
          └─────┬─────┘
                ▼
        独立审核 Worker 进程
                │
       data / outputs / runtime
```

界面不得直接运行审核逻辑。REST API 只调用应用服务；应用服务负责参数校验、任务管理和系统操作；Worker 继续通过请求、状态和事件文件与主进程交换信息。审核核心不得依赖 Web 包。

- Python 变量和函数统一使用清晰的 `snake_case`。

- 关键的令牌校验、路径保护、单实例、进程终止和原子写入代码必须包含中文注释。
- API 层不直接操作任务文件或启动子进程。
- `TaskManager` 不导入 Qt，也不模拟 Qt 信号。

## 6. 前端设计

### 6.1 技术和离线约束

- 使用普通 HTML5、CSS 和原生 JavaScript。
- 使用 Bootstrap 5.3.8 和 Bootstrap Icons 1.13.1 的发行资产。
- 所有 CSS、JavaScript、图标字体和许可证保存于发布包，不使用 CDN、远程字体或远程图片。
- 不引入 Node.js 或前端编译步骤。
- 使用 Windows 自带的 `Segoe UI`、`Microsoft YaHei UI` 和 `Microsoft YaHei` 字体族。
- `theme.css` 只负责品牌色、布局、间距、侧栏、状态色和深浅色适配，不复制 Bootstrap 已有控件。
- 页面使用语义化 HTML、键盘可访问控件和可见焦点状态。

Bootstrap 官方版本页确认 5.3.8 为 5.3 分支最新补丁版本；Bootstrap Icons 官方页面确认 1.13.1 为当前版本。构建时必须锁定这两个版本并记录文件 SHA-256。

### 6.2 页面结构

应用使用单个 `index.html` 和基于 `history.replaceState` 的本地页面状态，不引入前端路由库。

主导航：

- 审核任务
- 新建任务
- 使用帮助

顶部区域持续显示：

- “完全离线，数据仅保存在本机”状态。
- 当前规则版本。

侧栏底部显示：

- 本机服务状态。
- 当前运行任务数量。
- “退出审核器”操作。

### 6.3 审核任务页

展示：

- 正在审核数量。
- 当日完成数量。
- 当前待人工复核数量。
- 最近任务表格。
- 任务名称、任务编号、状态、创建时间、阶段和进度。
- 查看详情或打开结果操作。

任务列表每秒刷新一次。刷新不得重置当前页面、滚动位置或正在显示的确认弹窗。

### 6.4 新建任务页

字段：

- 任务名称：选择材料目录后默认使用目录名，允许修改。
- 待审核材料目录：必填，只能通过本地目录选择接口获得。
- 输出位置：只读预览，由程序自动生成。

运行前检查展示：

- 审核规则版本与完整性。
- LibreOffice 可用性。
- 输出根目录可写性。
- 业务资源完整性。

环境检查未通过时禁用“创建并开始审核”，同时显示明确缺失项。

### 6.5 任务详情页

展示：

- 任务状态和真实进度。
- 已完成与总工作单元数。
- 当前阶段、主体、业务和文件。
- 扫描材料、主体与范围校验、规则执行、生成结果四个阶段。
- 材料目录、输出目录、规则版本、创建时间和运行时间。
- 处理文件、审核意见、人工复核和失败项摘要。

操作：

- 安全停止任务。
- 打开输出目录。
- 打开统计表。
- 打开集中复核结果。
- 对失败或中断任务重新创建任务。

扫描完成前显示不确定进度；获得总工作单元后才显示百分比，不虚构时间进度。

## 7. REST API

所有业务接口使用 `/api/v1` 前缀，返回 JSON。成功与错误响应使用统一结构；错误响应包含稳定错误码和中文消息，不返回 Python 堆栈。

### 7.1 接口列表

| 方法 | 路径 | 成功状态 | 用途 |
|---|---|---:|---|
| `GET` | `/healthz` | `200` | 仅供启动和重复双击验证本机服务可达性 |
| `GET` | `/api/v1/system/status` | `200` | 获取服务、环境、规则版本和运行任务数 |
| `POST` | `/api/v1/input-directory-selections` | `201` 或 `200` | 创建一次目录选择；用户取消时返回 `200` |
| `POST` | `/api/v1/output-path-previews` | `200` | 根据输入目录返回只读的默认输出路径预览 |
| `GET` | `/api/v1/tasks` | `200` | 获取任务列表和任务摘要 |
| `POST` | `/api/v1/tasks` | `201` | 创建并立即启动审核任务 |
| `GET` | `/api/v1/tasks/{task_id}` | `200` | 获取任务详情、进度和结果摘要 |
| `POST` | `/api/v1/tasks/{task_id}/cancellations` | `201` | 创建安全停止请求 |
| `POST` | `/api/v1/tasks/{task_id}/terminations` | `201` | 创建经用户确认的强制终止请求 |
| `POST` | `/api/v1/tasks/{task_id}/output-openings` | `201` | 请求资源管理器打开该任务输出目录 |
| `POST` | `/api/v1/tasks/{task_id}/statistics-openings` | `201` | 请求系统打开该任务统计表 |
| `POST` | `/api/v1/tasks/{task_id}/review-openings` | `201` | 请求资源管理器打开集中复核结果 |
| `POST` | `/api/v1/shutdown-requests` | `201` | 创建退出或全部安全停止后退出请求 |

### 7.2 创建任务

请求只接受：

```json
{
  "display_name": "第二批省公司风控矩阵",
  "input_root": "D:\\报送材料\\第二批省公司风控矩阵"
}
```

客户端不得传入输出路径、规则路径、LibreOffice 路径或其他系统资源路径。后端根据便携目录和当前时间生成输出目录并完成所有路径校验。

输出路径预览只用于界面展示，不预占目录。正式创建任务时重新计算并原子保留目录；若期间出现同名冲突，创建任务响应中的实际 `output_root` 为最终结果，页面必须使用实际值替换预览。

### 7.3 目录选择

- 接口在独立 STA 线程中打开 Windows 原生目录选择框。
- 同一时间只允许一个选择框；重复请求返回 `409 DIRECTORY_PICKER_BUSY`。
- 用户取消时返回 `200`，`selected` 为 `false`，不视为系统错误。
- 接口返回绝对路径，但不扫描、上传或复制目录内容。
- 创建任务时重新验证路径存在、类型、可读性和与输出目录的关系，不能信任先前选择结果。

### 7.4 退出请求

请求使用明确模式：

```json
{
  "mode": "immediate"
}
```

`mode` 只允许：

- `immediate`：仅在没有活动任务时退出；存在活动任务时返回 `409 ACTIVE_TASKS_EXIST`。
- `cancel_active_tasks`：先为全部活动任务创建安全停止请求，全部进入终态后退出。

强制终止不通过退出接口隐式执行。页面必须逐个调用任务终止接口，并在所有目标进入终态后重新创建退出请求。

### 7.5 HTTP 错误语义

- `400`：请求结构或字段格式错误。
- `401`：访问令牌缺失或错误。
- `403`：Host、Origin、路径或资源访问被拒绝。
- `404`：任务或任务结果不存在。
- `409`：任务状态冲突、目录选择器忙、退出时仍有活动任务等。
- `422`：输入目录或运行环境不满足业务约束。
- `500`：无法归类的本地服务错误，详细堆栈只写本地日志。

## 8. 任务与进度模型

保留现有任务状态：

- `running`
- `cancelling`
- `completed`
- `partial`
- `failed`
- `cancelled`
- `interrupted`

页面每秒调用一次当前任务详情或任务列表接口。后端在每次读取时处理 Worker 退出检测和状态稳定化，不需要额外推送通道。

每个审核任务继续使用独立 Worker 进程、独立输出目录、独立 LibreOffice profile 和独立临时目录。浏览器标签页的数量不会影响 Worker 数量。

## 9. 输出目录

输出根目录固定为主程序目录下的 `outputs`，用户不能修改。

目录命名：

```text
outputs/<材料目录名>-YYYYMMDD-HHMMSS
```

约束：

- 材料目录名中的 Windows 非法字符替换为 `_`。
- 清理结尾空格和句点；清理后为空则使用 `审核任务`。
- 同名目录存在时追加 `-2`、`-3` 等递增序号。
- 不覆盖或复用已有任务目录。
- 输入目录不能是输出目录、包含输出目录或位于输出目录内部。
- 原始材料保持只读，正式结果只写入任务输出目录。

## 10. 安全设计

### 10.1 网络边界

- Uvicorn 只绑定 `127.0.0.1`，不得绑定 `0.0.0.0`、主机局域网地址或 IPv6 全局地址。
- 操作系统分配随机空闲端口，不使用固定公开端口。
- 不配置 CORS；任何跨域 API 请求都被拒绝。
- 请求必须通过允许的 `Host` 和 `Origin` 校验。
- 修改状态的请求必须携带与本机页面完全一致的 `Origin`；只读请求允许同源 `Origin` 或浏览器未发送 `Origin`，但仍必须通过 Host 和令牌校验。

### 10.2 访问令牌

- 每次服务启动使用密码学安全随机源生成一次会话令牌。
- 浏览器首次打开的 URL 临时携带令牌。
- 页面将令牌保存到 `sessionStorage`，随后立即用 `history.replaceState` 从地址栏移除。
- 所有 `/api/v1` 请求必须通过 `X-Local-Token` 请求头携带令牌。
- 令牌只在当前服务生命周期有效，不作为长期凭据。
- 健康检查只返回服务可达性，不返回令牌、文件路径或任务信息。
- 健康检查不修改状态，只允许回环地址访问，并执行 Host 校验。

### 10.3 浏览器安全

- 设置严格 CSP，只允许同源脚本、样式、字体和图片。
- 设置 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` 和禁止嵌入页面的响应头。
- 前端不使用 `innerHTML` 插入任务名称、路径、日志或错误消息。
- 任务名称和路径按纯文本渲染。

### 10.4 本机系统操作

- 打开目录和文件接口只接受任务编号，不接受客户端提供的任意路径。
- 后端从已验证任务记录解析目标，确认目标仍在该任务输出目录内后才调用系统打开。
- 强制终止前重新读取任务状态并核对 Worker PID，避免终止已复用 PID 的无关进程。
- 目录选择器一次只接受一个请求，避免多标签页重复弹窗。

## 11. 启动、重开与退出

### 11.1 首次启动

1. 解析程序根目录。
2. 获取 Windows 单实例锁。
3. 清理经验证已经失效的旧会话文件。
4. 运行关键资源检查。
5. 生成访问令牌。
6. 启动绑定于 `127.0.0.1` 随机端口的本地服务。
7. 原子写入 `data/server-session.json` 当前会话文件。
8. 服务健康检查通过后打开默认浏览器。

应用使用 PyInstaller windowed 模式，不显示控制台窗口。

会话文件只包含 `schema_version`、主服务 PID、端口、访问令牌和启动时间。它用于同一便携目录中的第二次启动重新打开页面，不属于长期任务数据；正常退出时删除。令牌的安全目标是阻止浏览器中的其他站点调用本机接口，而不是对已经能够读取当前用户本地文件的进程建立权限边界。

### 11.2 重复双击

第二个进程发现单实例锁已存在后：

1. 读取会话文件。
2. 校验记录的 PID 和本机健康接口。
3. 使用当前端口和令牌重新打开默认浏览器。
4. 第二个进程立即退出。

若会话文件存在但 PID 或健康接口无效，则将其视为残留状态；新主进程取得锁后覆盖会话文件。

### 11.3 浏览器关闭

关闭一个或全部浏览器标签页不会向后端发送退出请求。服务和 Worker 保持运行。用户再次双击 EXE 即可重新打开页面。

### 11.4 退出审核器

- 没有活动任务时，`shutdown-requests` 关闭服务并删除会话文件。
- 存在活动任务时，页面提供“继续后台运行”和“全部安全停止后退出”。
- 选择安全停止后，后端为所有活动任务创建取消请求，等待进入终态，再关闭服务。
- Worker 超过既定等待时间仍未退出时，页面列出未响应任务，并要求用户再次确认是否强制终止。
- 强制终止只作用于重新核对后的 Worker PID。
- 电脑关机、进程崩溃或被外部结束后，下次启动将仍处于运行状态的任务标记为 `interrupted`。

## 12. 错误处理与日志

- 用户可处理的错误以中文消息显示，并提供明确下一步。
- API 错误包含稳定 `error_code`，前端不根据中文文案判断流程。
- 主服务日志写入 `data/logs/server.log`，采用大小轮转。
- Worker 日志继续写入任务目录 `_task/worker.log`。
- 前端不得展示堆栈、令牌、内部 Python 路径或其他任务的材料路径。
- 单个任务状态损坏时隔离该任务并显示警告，不影响任务列表其余记录。
- 静态资源或关键运行资源校验失败时拒绝创建任务，但允许打开页面查看具体诊断结果。

构建规则：

- 使用 PyInstaller `onedir` 和 `windowed` 模式。
- Python、FastAPI、Uvicorn、审核核心及普通 Python 依赖进入 `_internal`。

- `manifest.json` 记录所有 `runtime` 文件的相对路径、大小和 SHA-256。
- 启动时校验运行所需资源；构建和发布验证校验完整清单。
- `runtime/licenses` 必须包含 Python、FastAPI、Uvicorn、Bootstrap、Bootstrap Icons、LibreOffice、PyInstaller 和其他发布组件要求的许可证或声明。
- 用户必须整体移动发布目录，不能只复制 EXE。
