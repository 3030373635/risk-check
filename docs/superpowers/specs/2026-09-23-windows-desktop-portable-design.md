# 风控矩阵审核器 Windows 免安装桌面端设计

## 1. 文档信息

- 设计日期：2026-09-23
- 目标版本：桌面端 v2.0.0
- 目标平台：Windows 10/11 64 位
- 交付方式：免安装目录版 ZIP
- 运行模式：完全离线

## 2. 背景与目标

现有风控矩阵审核器是本地 Python 命令行程序，审核核心、规则包、基准材料、结果写回和运行日志已经具备。当前交付方式要求用户准备 Python、依赖和 LibreOffice，并通过命令行传入材料和输出路径，不适合不了解代码的业务用户。

桌面端的目标是保留现有审核能力，为普通用户提供一个无需安装开发环境、无需使用命令行的 Windows 应用。用户解压交付包后双击主程序，即可选择材料、执行审核并打开结果。

成功标准：

1. 用户电脑无需预装 Python、Qt 或 LibreOffice。
2. 用户无需管理员权限，不运行安装程序，不写注册表。
3. 用户能够在界面内完成材料选择、输出位置选择、审核启动、进度查看和结果打开。
4. 审核期间界面保持响应，工作进程异常不导致桌面程序整体退出。
5. 原始材料始终只读，不提供覆盖原文件的操作。
6. 桌面端审核结果与审核核心的业务规则保持一致。

## 3. 产品范围

### 3.1 第一版包含

- Windows 10/11 64 位桌面程序。
- 待审核材料文件夹选择及拖放。
- 输出文件夹选择，并可自动生成带日期或任务名的子目录。
- 审核前环境和资源完整性检查。
- 审核任务启动、取消及后台运行。
- 扫描材料、主体校验、规则执行、汇总输出等阶段进度。
- 当前主体、业务、文件和提示数量展示。
- 完成结果摘要及输出目录、审核统计表、处理报告快捷入口。
- 本机历史任务记录。
- 程序版本、规则版本、LibreOffice 和基准资源诊断。
- 诊断报告导出。
- 默认折叠的高级规则选项。
- 浅色和深色主题自适应。

### 3.2 第一版不包含

- 用户账号、权限或登录。
- 云端上传、云端同步和联网审核。
- 自动联网更新。
- 规则可视化编辑器。
- 多台电脑之间同步历史记录。
- 同时运行多个审核任务。
- Windows ARM、32 位 Windows、macOS 和 Linux 支持。
- 面向外部程序的 HTTP 或 REST API。

## 4. 用户操作流程

### 4.1 首次启动

1. 用户解压 `风控矩阵审核器-v2.0.0-Windows-x64.zip`。
2. 用户双击 `风控矩阵审核器.exe`。
3. 程序检查审核引擎、规则包、基准材料、主体清单和内置 LibreOffice。
4. 检查通过后显示“环境正常”；检查失败时说明缺失项和处理方法。

### 4.2 执行审核

1. 用户选择或拖入待审核材料文件夹。
2. 程序建议一个新的输出目录，用户可以修改。
3. 用户按需展开高级选项，临时调整允许开放的规则开关。
4. 用户点击“开始审核”。
5. 界面进入运行状态，持续显示阶段、进度、当前业务、文件和提示。
6. 审核完成后展示单位数、业务数、审核意见数和需人工确认项数。
7. 用户点击按钮打开结果目录、审核统计表或详细处理报告。

### 4.3 失败与取消

- 可恢复的材料问题在界面中说明具体文件、原因和建议处理方式。
- 程序内部异常提供简短错误编号，并允许导出不包含原始材料的诊断报告。
- 用户取消任务时，界面要求再次确认，然后终止审核工作进程；已经完整生成的结果保留并明确标记为“未完成”。

## 5. 界面设计

桌面端采用 Windows 11 风格的现代化界面，使用卡片、圆角、清晰状态色和适量动画。界面不追求复杂仪表盘，优先保证普通用户可以快速完成审核。

### 5.1 主导航

- 开始审核
- 历史记录
- 设置与诊断

### 5.2 准备审核页

- 待审核材料选择卡片。
- 结果保存位置选择卡片。
- 运行前检查状态。
- 折叠的高级选项。
- 突出的“开始审核”主按钮。
- “完全离线、原文件不修改”提示。

### 5.3 审核进度页

- 总体进度百分比。
- 已完成业务数和总业务数。
- 扫描材料、主体与范围校验、执行规则、汇总输出四阶段状态。
- 当前主体、业务及文件名称。
- 已用时间和当前提示数量。
- 最小化到后台和取消任务按钮。

### 5.4 审核结果页

- 成功、部分完成或失败状态。
- 审核单位、业务、意见和人工确认项摘要。
- 打开结果目录和审核统计表按钮。
- 未识别文件、主体代码待确认等重点提示。
- 开始新审核入口。

### 5.5 历史记录页

- 材料名称、完成时间、结果状态和意见数量。
- 打开结果或查看详情操作。
- 历史记录只保存任务元数据及输出路径，不复制原始材料。

### 5.6 设置与诊断页

- 程序版本和规则包版本。
- 审核引擎、LibreOffice、基准材料及主体清单状态。
- 导出诊断报告入口。
- 第一版不向普通用户开放规则文件编辑能力。

## 6. 技术架构

### 6.1 技术选型

- 桌面框架：PySide6。
- 界面层：Qt Quick/QML。
- 审核核心：现有 `risk_audit` Python 包。
- 独立交付：`pyside6-deploy`/Nuitka standalone。只有在 Windows 实机验证证明其无法正确收集项目依赖时，才切换为 PyInstaller onedir，并使用相同的目录结构和验收标准。
- Excel 转换：随包交付并经过验证的 LibreOffice Windows 运行环境。
- 本地任务记录：第一版使用结构化 JSON，避免引入额外数据库依赖。

### 6.2 模块边界

```text
desktop_app
├── presentation       QML 页面、组件、主题和窗口状态
├── controllers        页面行为、输入校验和任务状态协调
├── task_manager       审核工作进程启动、事件接收、取消和退出
├── diagnostics        程序资源、规则、基准和 LibreOffice 检查
├── history            本机任务元数据读写
└── platform           Windows 文件打开、路径和进程适配

risk_audit
├── audit_engine       现有审核编排和业务规则
├── resources          规则包、基准材料和主体清单
└── worker_entry       桌面端审核工作进程入口
```

每个模块只承担一种职责。所有新增函数必须包含用途、参数和返回值注释；关键的进程、文件完整性和输出保护逻辑必须添加中文注释。变量命名统一使用清晰的英文 snake_case，QML 属性统一使用 camelCase。

### 6.3 进程模型

桌面界面进程不直接运行耗时审核。每个审核任务启动一个独立工作进程：

```text
QML 界面
  ↓ 用户操作
Python 控制器
  ↓ 启动和管理
审核工作进程
  ↓ 调用
risk_audit 审核核心
```

采用独立进程的原因：

- Excel 批量处理不会阻塞界面事件循环。
- 审核核心异常不会直接关闭桌面窗口。
- 用户取消任务时可以明确终止工作进程。
- 后续审核核心升级与界面层保持清晰边界。

第一版一次只允许一个审核任务运行。运行期间可以查看进度，但不能启动第二个任务。

### 6.4 任务事件

工作进程通过标准输出发送逐行 JSON 事件，界面通过标准错误或独立日志文件保留诊断信息。事件至少包含：

```json
{
  "event": "business_progress",
  "stage": "audit",
  "completed": 17,
  "total": 25,
  "entity_name": "示例单位",
  "business_name": "设备（资产）管理",
  "file_name": "风控矩阵.xlsx",
  "message": "正在执行审核规则"
}
```

事件类型包括：

- `task_started`
- `scan_progress`
- `validation_progress`
- `business_progress`
- `warning`
- `task_completed`
- `task_failed`
- `task_cancelled`

事件字段使用统一名称；新增事件需在任务事件模型和测试中明确声明。当前项目不需要对旧命令行事件格式保持兼容，可以为桌面端建立清晰的新事件协议。

## 7. 数据与目录设计

### 7.1 交付目录

```text
风控矩阵审核器-v2.0.0/
├── 风控矩阵审核器.exe
├── runtime/
│   ├── python-and-qt/
│   └── libreoffice/
├── rules/
├── baselines/
├── resources/
├── licenses/
├── 使用说明.pdf
└── 版本说明.txt
```

用户必须整体移动该目录，不能只复制主程序。启动时程序校验必要文件；目录不完整时拒绝执行审核并给出缺失清单。

### 7.2 用户数据

程序资源保持只读。本机设置、历史记录和诊断缓存写入：

```text
%LOCALAPPDATA%\RiskAuditDesktop\
├── settings.json
├── history.json
├── logs/
└── diagnostics/
```

正式审核输出只写入用户选择的输出目录。程序不把原始材料复制到 `%LOCALAPPDATA%`。

### 7.3 输出保护

- 默认创建新的输出子目录。
- 发现输出目录与输入目录重叠时阻止运行。
- 目标路径已经存在同名文件时拒绝启动，并要求用户选择新的输出目录。
- 取消或异常后保留已经完整生成的文件，并将任务标记为未完成。

## 8. LibreOffice 运行环境

- 随交付目录提供经过审核器验证的 Windows 64 位 LibreOffice 运行环境。
- 审核器始终优先调用随包版本，不依赖用户电脑已有版本。
- LibreOffice 使用独立临时用户配置目录，禁用宏、活动内容和外部链接更新。
- 每次启动审核前检查 `soffice.exe` 及必要运行文件是否存在。
- Windows 真实 `.xls`、BIFF `.et`、OOXML `.et` 和 `.xlsx` 材料必须在目标 Windows 机器进行兼容性验收。
- 交付包保留 LibreOffice 及其他第三方组件的许可证和来源说明。

## 9. 错误处理

### 9.1 用户可处理错误

- 输入目录不存在或无可审核材料。
- 输出目录不可写、与输入目录重叠或已有冲突文件。
- 材料仍在 Office/WPS 中被占用。
- 主体证据冲突。
- 材料格式无法识别。

提示必须包含文件或目录、具体原因和下一步处理建议，不直接展示 Python 异常堆栈。

### 9.2 环境错误

- 规则包缺失或校验失败。
- 基准材料缺失或哈希不一致。
- LibreOffice 缺失或无法启动。
- 交付目录不完整。

环境错误在审核前阻止任务启动，并允许导出诊断报告。

### 9.3 程序异常

- 界面显示统一错误编号、简短说明和日志位置。
- 完整异常堆栈只写入本地日志。
- 诊断报告包含版本、资源校验结果、任务阶段和错误信息，不包含原始材料内容。
- 若已有部分完整输出，界面明确提示“部分结果已保留，但本次任务未完成”。

## 10. 安全与隐私

- 审核过程完全离线，不创建网络连接。
- 原始材料不上传、不写入历史记录、不进入诊断报告。
- 输入文件只读，正式结果写入独立输出目录。
- LibreOffice 转换使用隔离配置并禁用活动内容。
- 程序资源通过清单和 SHA-256 校验发现误删或篡改。
- 正式对外发布时建议对主程序签名，减少 Windows SmartScreen 警告。

## 11. 打包与交付

交付文件为：

```text
风控矩阵审核器-v2.0.0-Windows-x64.zip
```

交付要求：

- 解压后直接双击主程序，不运行安装器。
- 不要求管理员权限，不写注册表，不创建系统服务。
- 不采用单文件自解压模式，避免启动时重复释放大体积资源及杀毒软件误报。
- Windows 程序必须在 Windows x64 环境构建和测试，不能使用 macOS 交叉生成最终包。
- 内测包可以不签名；正式广泛分发前建议完成代码签名。
- 第一版采用整体 ZIP 替换升级，不实现联网自动更新。

## 12. 测试与验收

### 12.1 自动化测试

- 保持现有审核核心测试通过。
- 为任务事件模型、参数校验、历史记录和诊断检查新增单元测试。
- 为工作进程正常完成、业务错误、内部异常和取消新增集成测试。
- 校验输入输出目录重叠、输出冲突和资源缺失等保护逻辑。
- 验证界面控制器在异常事件后恢复为可再次运行状态。

### 12.2 Windows 实机测试

至少覆盖：

- Windows 10 x64 和 Windows 11 x64。
- 无 Python、无 LibreOffice 的干净电脑。
- 中文用户名、中文路径、空格路径和较长路径。
- 普通用户权限及无管理员权限场景。
- Windows Defender 开启场景。
- `.xlsx`、`.xls`、两类 `.et`、`.docx`、`.doc` 和 `.pdf` 材料。
- 大批量材料、超大工作表、隐藏工作表及异常中断。
- 从本地磁盘、U 盘和只读来源读取材料。

### 12.3 验收标准

1. 干净 Windows 电脑解压后可以直接启动。
2. 环境检查能够识别完整包和损坏包。
3. 审核运行时界面持续响应，进度信息与实际阶段一致。
4. 正常任务可以生成审核副本、统计表、辅助报告和日志。
5. 取消和异常不会覆盖原始材料，也不会把未完成任务显示为成功。
6. 同一测试材料的桌面端结果与审核核心基准结果一致。
7. 历史记录可重新打开仍存在的输出目录，并能识别已移动或删除的路径。

## 13. 主要风险与控制措施

### 13.1 交付包体积较大

LibreOffice 和 Qt 会明显增加 ZIP 体积。第一版不打包默认关闭的本地语义模型，只包含审核必需资源；发布前记录压缩包大小和解压后大小。

### 13.2 Windows 转换兼容性

现有转换能力主要需要在真实 Windows 环境补充验收。使用固定的内置 LibreOffice 版本和真实样本回归，不能只验证程序能够找到 `soffice.exe`。

### 13.3 杀毒软件误报

避免单文件自解压程序；保留稳定的目录结构；正式版本进行代码签名，并在 Windows Defender 开启条件下验收。

### 13.4 用户误删运行文件

启动时执行资源完整性检查，缺失时给出明确文件清单；使用说明强调必须整体复制和移动程序目录。
