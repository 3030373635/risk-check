# 批量复核优化及验证说明（v1.2.11）

本版程序及规则包均为1.2.11。运行过程继续使用本地确定性代码，不调用大模型或在线接口。验证对象为工作区原始信通10份、湘西199份工作簿，使用与优化前相同的会计主体清单、0818基准及分主体应报范围。

## 一、读取规则

| 情形 | 当前处理 |
|---|---|
| 同一业务字段同时有可见列和隐藏列 | 优先可见列，隐藏列作为参考，不参与该字段审核 |
| 某业务字段仅存在于隐藏列 | 正常读取，包括原文、公式缓存、删除线等信息 |
| 选定的可见列某行为空 | 按实际空值审核，不从隐藏参考列逐行回填 |
| 多个可见列内容不同 | 根据明确的本单位限定、部门岗位配对、责任主体与载体的模板类型等证据选择；仍不能确定则集中确认 |
| 表头带有其他单位名称 | 不直接当成本单位字段；保留候选、坐标、归属依据 |
| 岗位表改名或表头下移 | 结合前30行的必需字段组合识别，不能仅因标题不含“职责”就跳过 |
| 表名仍写其他公司 | 读取实际业务表，集中提示确认表名及内容归属，不自动认可本地化 |
| 隐藏工作表 | 沿用1.2.10口径：默认不纳入，单独输出处理提示；与隐藏列政策区分 |

新增岗位字段别名：“岗位人员名称”“岗位人员姓名”“角色（根据下拉框填写）”。已有别名仍保留。受约束的表头解析支持“部门（综合管理部）”、带本单位简称的适用情况和责任主体等写法。不会把“适用层级”或修改动作直接解释为本单位适用结果。

每次运行的 `inventory.json` 中，`preservation.column_selections` 记录选择列、候选列、隐藏状态、表头、坐标及原因。XLS转换新增列隐藏状态校验，继续核对缓存值、合并范围、工作表可见性；校验失败即停止该文件转换。

## 二、审核规则及能力版本

| 规则 | 本次调整 | 能力版本 |
|---|---|---|
| 第1条 | 已确认主体的规范简称可用于文件命名核对，不能仅凭简称反向认定会计主体 | required_documents@2 |
| 第3条 | 按逻辑业务字段与0818基准比较，允许列重排及已确认表头别名；未知表头仍保留层级和数量核对。区分“未能读取”与“确认缺失” | schema_contains@2 |
| 第5条 | 部门分列填写时，去除已确认的本单位名称前缀后核对岗位；主体、业务、变体和措施编号边界不变 | responsibility_coverage@3 |
| 第8条 | 姓名或角色列未识别时提示先确认字段，不能直接写成该行未填写；读取到空值时仍按空值检查 | roles_same_duty@2 |
| 第9条 | 分别检查载体列与职责正文；区分载体、明确的制度依据、执行动作及文件内部内容；支持当前措施唯一的括号简称、明确“或”选项及完整名称连写 | set_subset@3 |
| 第10条 | 责任属性兼容“准确、真实、完整”等形容词，不机械要求带“性”；否定表达及缺少责任关系仍不通过 | responsibility_phrase@3 |

第4、7条继续停用；第6条保持降级处理；第11条经办／审核／审批与主体／审核／审批责任的要求保持；第12条排序要求保持。第13条保持同一主体、业务、变体、控制措施编号范围内的删除原文检查，短字词也检查；同一措施最终有效内容仍保留的原文允许引用。R09的别名及词表不用于放宽R13。

识别词表只帮助辨认名称，不能代表该名称已获本措施允许引用。无法唯一拆分的连写词、多个括号全称共享同一简称等情况不会自动通过。

## 三、减少重复复核

行级 `findings.json` 完整保留，另外生成 `复核事项.csv`、`review_tasks.json`、`集中复核事项.md`。每条意见恰好归入一个事项，保留原意见键、所有文件／工作表／行位置。

- 字段问题按文件、工作表、字段集中处理，先确认读取来源。
- 相同职责句式的解析问题供维护人员集中补规则；更新后仍逐行对照各单位自己的矩阵。
- 岗位对应按本单位、业务、变体及具体称谓归并；确认名称对应后，仍需逐措施检查是否覆盖。
- 载体引用问题按本单位、业务、变体、措施编号、引用名称及当前载体集合归并。
- 经办审核同人问题将同一人员的对称行对归并。
- 责任表述、人员空值、适用性填法等集中列示，同时保留全部涉及行。

归并不删除意见，不降低严重程度，也不批量判通过。事项始终保存 `resolution_applies_automatically=false`。适用性相同不等于每条措施可以给出同一个结论。

## 四、确认结果如何进入程序

新增可选规则资源 `input_overrides.json`，用于保存人工已确认的特定文件字段列。必须同时限定相对文件路径、源文件SHA-256、工作表、逻辑字段、列号及确认原因；文件变化后拒绝继续套用。人工审核意见列不能作为业务字段。当前发布包该资源为空，没有把未确认候选自动写成事实。

新增 `--scope-file`，按会计主体代码分别配置应报范围。文件中的每个主体必须在范围文件中有明确入口；未知主体使用空字符串键显式保留。运行快照记录范围内容及哈希。县公司、地市本部、分子公司分别运行自身范围，不混用岗位清单。

更新配置仍应遵循草稿、校验、试跑、冻结发布、激活流程。旧能力版本及旧冻结规则包保留。旧运行重现需要对应代码版本，不能只切换规则包。

信通待核实减少22.8%，湘西减少47.4%。这表示在相同范围内的程序输出变化，不是总体准确率，也不表示减少的全部意见均为误报。补读正式岗位表和修正字段选择后，还会新增应查问题。

湘西补读8张岗位表、1,047条记录，读取记录由31,972增至33,019；信通仍为1,347条。信通、湘西分别有9、218次“独有隐藏字段”选择，均纳入读取。龙山07业务改用可见正式岗位列后，消除65条旧隐藏岗位造成的拆分提示，同时保留4行可见部门、岗位空白的8条问题。

370项测试通过；最终代码分别完整运行两套材料，从文件扫描、Excel读取、XLS转换校验、全部已启用规则执行到事项归并。209份源文件哈希与优化前一致；23份BIFF工作簿（含按BIFF读取的ET）转换校验均通过；无规则执行失败。隐藏表按已确认口径跳过，信通36张、湘西637张。

信通人工标注共432项，其中401项可按现行分类对照；原来匹配的328项本版仍全部匹配。73项原有未覆盖项保留在报告中：部门9项、岗位62项、同人2项。这些不是本次新增遗漏，也不能当作已经验证正确。未标注行不视为负例。

第13条信通仍为13条；湘西由235条增至316条，增加81条，旧问题无减少。对所有第13条问题的338处原文匹配另行核验了主体、业务、变体、编号、删除片段、职责原文及最终有效内容。

## 六、判断与仍有的限制

本版修复了已识别的主要批量读取问题，减少了大量无效逐行核实。它仍不能替代全部业务判断。

1. 湘西有8组可见同名列冲突，不能仅凭位置猜测；集中确认后可通过受源文件哈希约束的配置重审。
2. 湘西有8张表的标题保留其他单位名称，需要确认材料归属。另有农服公司7份文件缺少可确认主体，2份文件业务编号冲突，其中1份与前者重叠；这些旧问题继续显式保留。
3. 复合载体的残余解析问题仍存在，例如已识别“储备库的储备项目记录”，但“储备库”仍被提取为待解析片段。应在“解析规则补充”事项集中处理，不能把此类提示直接作为单位填错的结论。
4. 部门、岗位泛称词表仍有覆盖缺口；纯文本职责相同判断也不能完全识别同义表达。报告列出了人工曾指出但程序未覆盖的原文，不声称全部通过。
