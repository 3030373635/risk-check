# 风控矩阵及三清单本地审核器

当前程序及默认规则包版本为 **1.9.19**。本版新增第二批 8 份省公司模板，并将模板身份从业务展示编号升级为全局唯一 `business_id`。第一批、第二批及后续批次可重复使用 `01`、`02` 等编号；程序按报送相对路径中的业务名称别名选择业务，再在该业务内选择模板变体。1.9.18及更早规则包继续保留，仅用于回滚、差异对比和回归测试，不代表当前口径。

当前业务材料支持 `.xlsx`、`.xls` 和 `.et`。`.et` 按文件真实签名分流：OOXML 内容按 XLSX 读取，BIFF/OLE 内容按 XLS 读取并转换；未知 WPS 专有结构保留在材料清单中并报告无法解析。ET 审核副本统一输出为 `.xlsx`，原文件不修改。说明或申请材料另支持 `.docx`、`.doc` 和 `.pdf`。

审核先扫描整批材料并校验会计主体。名称未匹配名册、清单中缺少单位代码或识别代码不在名册中时，按本次单位目录或明确报送名称隔离分组并继续审核；正式代码保持待确认，不修改主体名册。最终主体和业务结果的`entity_registry_status`、`entity_registry_message`记录匹配状态，`本次审核范围.md`及`主体代码待确认.md`标注“主体不在会计主体清单中”或具体待确认原因，`runs/<run-id>/_risk_audit`保存审核辅助报告；清单外名称不用于推定名册适用层级。仅主体证据冲突时立即终止审核或试跑，在`audit.log`记录文件路径、原因及识别证据，保存`主体代码待确认.md`和`entity_alerts.json`，命令退出码为`2`。扫描后立即记录本次主体名单，提前检查整批潜在输出路径冲突，再统一加载一次公共基准。审核单元为“主体＋`business_id`＋矩阵变体”；`business_code`只用于展示。每个单元的矩阵和三清单一起解析，仅使用对应公共基准审核，立即输出后再处理下一个业务，不跨业务或电压变体比较。每个业务的结果和转换副本保存在`entities/0001/businesses/0001/`，主体汇总仍保存在`entities/0001/`，批次摘要的`business_results`列出全部业务结果。主体说明用于存在性检查并原样复制一次；缺报单个业务不等于整个主体未报送。后续业务异常时保留已输出副本和主体进度，全部业务结束后再生成批次汇总。试跑采用相同业务处理顺序，记录日志和结果，但不写审核副本。

审核进度、逐文件读取明细、完整路径、运行标识、警告及异常堆栈统一保存在`runs/<run-id>/audit.log`，不输出到终端。命令执行结果仍以 JSON 写入标准输出。运行目录建立前的版本、LibreOffice 路径等启动错误仍由`run_audit.py`写入标准错误流，此时不会生成`audit.log`。

## 安装

在项目根目录执行：

```bash
python3 -m venv 审核器/.venv
审核器/.venv/bin/pip install -r 审核器/requirements.lock
审核器/.venv/bin/pip install -e 审核器
# 可选：仅在需要启用本地Embedding候选时安装
审核器/.venv/bin/pip install -r 审核器/requirements-semantic.lock
```

`.xls` 只使用随运行时提供的无头 LibreOffice 转换。转换在一次性隔离 profile 中执行，profile 明确禁用宏、活动内容和外链更新；转换后恢复 BIFF 缓存值，并逐格核对缓存值、合并范围以及 `visible`/`hidden`/`veryHidden` 状态，核对失败即停止，不生成正式副本。该转换不宣称全保真：公式表达式由 LibreOffice 转换，富文本字体已恢复，本次独立验证覆盖了文本删除线，全部字体样式和嵌入对象尚未逐项验证；这些边界会写入 preservation 报告。

## 审核和验证

```bash
审核器/.venv/bin/risk-audit config-validate 审核器/rulepacks/releases/1.7.0

审核器/.venv/bin/risk-audit audit \
  --input '审核/国网湖南信通公司第一批风控矩阵应用落地资料-9.11初审' \
  --output 'outputs/01a09d8b-4204-7c53-979d-e66fe1726a68/信通验证-v1.7.0' \
  --project-root . --runs-root runs
```

输出保留输入包中的相对目录结构；`.xls` 和 `.et` 生成同名 `.xlsx` 审核副本，原始文件不变。默认仅在识别出的可见正式业务表增加一列“审核意见”；隐藏工作表保留且不写意见。`9.11初审` 保留且不进入解析字段、事实或规则执行。`审核统计表.xlsx`直接保存在输出目录根部，程序意见的单元格归属保存在`runs/<run-id>/_risk_audit/ownership.json`；重跑会从同一输出目录最近一次运行读取归属，清理可确认的旧程序意见，检测到人工改写则保留并在运行警告中提示。

项目根目录的 `audit-config.json` 默认停用 `R03`，同时关闭规则三的全部子规则。需要在某次审核中临时启用时，在 `audit` 或 `trial` 命令中增加 `--enable-rule R03`；该参数不修改默认配置。可通过 `--config <文件路径>` 改用其他运行配置。最终生效状态保存在运行快照的 `runtime_rule_selection` 中。

人工对照必须在算法结束后单独运行：

```bash
审核器/.venv/bin/risk-audit manual-extract --input '<上面的输入目录>' --output runs/<run-id>/manual_labels.json
审核器/.venv/bin/risk-audit manual-compare --labels runs/<run-id>/manual_labels.json --findings runs/<run-id>/findings.json --output runs/<run-id>/manual_comparison.json
```

人工对照只报告已知正例及范围差异，不把未标注行当负例，也不输出总体准确率。

校验会拒绝未知规则字段、参数、逻辑字段、能力版本、模板变量、重复 ID、未实现能力（包括直接开启 R07）和同优先级同范围的覆盖冲突。新增使用 `capabilities` 命令列出的已有能力的规则，不需要修改解析器、引擎或写回器。

## 运行产物

每次运行在 `runs/<run-id>/` 保存 `snapshot.json`（规则包/能力/输入哈希）、`inventory.json`、`findings.json`、`statuses.json`、`limitations.json`、`warnings.json` 和 `summary.json`。错误配置在任何正式输出写入前终止。源文件在运行前后都校验 SHA-256；输出目录不会被输入扫描。v2将泛称或简称对应不明写入findings.json和单位审核意见，标注“待核实”。1.3.0的limitations.json保留全部技术及依赖限制，internal_diagnostics.json和内部处理事项.csv按共同原因归并；存在限制时状态为partial，不能视为通过。`write_completed`表示副本写入完成，`has_check_limits`表示仍有核对限制，两者可同时为真。

v1.7.0另输出 `capability_diagnostics.json` 和 `程序判定能力明细.csv`，按确认应审范围区分材料前置问题、适用含义未确定、句式未支持及字段来源待查，保留原文坐标与已有材料意见。分类不代表通过，也不代表这些记录全是程序错误。

## 从其他单位业务表构建识别词表

```bash
审核器/.venv/bin/risk-audit vocabulary-build \
  --input '审核/星通公司' \
  --input '审核/湘西公司风控矩阵(20260911上报版）' \
  --holdout-key '国网湖南省电力有限公司龙山县供电分公司' \
  --output '审核器/vocabulary/下一次词表' \
  --pack '审核器/rulepacks/releases/1.7.0'
```

输出目录必须是新目录。命令生成词条、完整来源、文件疑点、解析记录及来源哈希，不修改源表，不自动发布规则包。主体/业务不确定、明确历史表及仅存在于留出材料的词条只保留候选。审核意见和人员姓名不进入词表。

`terminology.json` 是可选规则资源：载体用于完整名称识别，部门和岗位用于候选梳理；出现过不代表合格，不自动批准别名。确认并校验后，将它纳入新规则草稿再冻结发布。示例词表和待确认事项见上述优化验证报告。现行R09只核对措施编号；载体引用及其语义候选不再执行。R13按删除原文直接比对，不使用载体别名词表。
