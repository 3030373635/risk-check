# 第二批模板业务识别说明 v1.9.19

## 更新内容

v1.9.19 将省公司模板配置升级为 `schema_version: 2.0`，登记第一批 11 份、第二批 8 份，共 19 份模板。配置中共有 18 个全局唯一业务；`03 电网基建`包含两个电压变体。

业务唯一身份使用 `business_id`。`business_code`继续保留在审核范围、结果及报告中，但只用于展示，不再作为模板索引或审核隔离主键。因此以下重复编号不会互相选择模板：

- `01`：营销售电、股权（产权）管理；
- `02`：交易与购电、财务管理；
- `03`：电网基建、合同管理；
- `08`：数字化与研发投入、设计监理业务。

第二批新增的 `28`教育培训、`29`施工建设、`30`物业后勤、`31`供电服务也通过业务名称识别，不再受原 `01`至`10`编号正则限制。

## 识别规则

程序使用报送文件相对于输入根目录的完整路径进行匹配。路径和业务别名统一执行 Unicode NFKC、英文小写、空白及常见括号和连接符归一化。编号不参与业务选择。

路径命中多个业务别名时，唯一最长别名胜出；最长别名仍并列时停止该材料的模板映射并报告冲突。业务确定后再选择变体；电网基建未写明电压范围时不会猜测模板。

## 配置与输出

当前模板目录位于 `rulepacks/releases/1.9.19/baseline_registry.json`。每个模板继续固定相对路径和 SHA-256，文件缺失、内容变化或解析失败时停止审核。

`inventory.json`、`findings.json`、业务结果及自动审核范围同时保存 `business_id`和`business_code`。手动范围文件须为每个业务提供：

```json
{
  "business_id": "equity_management",
  "business_code": "01",
  "variant_id": "default",
  "required": true
}
```

历史规则包保持原文件不变，仅用于复核旧运行；默认激活规则包为 v1.9.19。
