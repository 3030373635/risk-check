# Embedding优化蓝图 v1.5.0

本轮接续1.4.1，保留本地BGE小模型、CPU两线程和离线运行。载体引用检查继续停用，第13条仍按同编号删除原文比较。模型优化只影响内部候选，不凭分数撤销单位意见。

| 已发现成因 | 本轮实施 | 验收依据 |
| --- | --- | --- |
| 单位全称混入岗位向量，稀释部门岗位信息 | 验证归属后拆出部门、岗位分别编码，保留原文和归属依据 | 同一岗位不同本单位全称的候选顺序一致；外国/外单位前缀不能被删除 |
| 无论是否相关都返回前三项 | 先排除职级、正副职、角色及归属冲突，再按字段分数筛选；没有合格候选就拒绝推荐 | 经理/副经理、主任/副主任、审核/审批、不同职员等级等反例不得作为可对应候选 |
| 候选没有目标单元格，核对仍需翻表 | 每个候选携带同主体、业务、矩阵类型、措施编号下的原始部门岗位列及源文件哈希 | 每项候选能反查目标原表；禁止跨措施借用记录 |
| 相同关系逐措施重复导出，候选词表膨胀 | 同一主体、业务、矩阵类型下按部门岗位关系归组，保留全部措施及双向来源 | 组内明细完整，不能因其他措施出现过就认定当前措施已覆盖 |
| 反复查询磁盘缓存和重复编码 | 增加有上限的内存向量缓存；仅编码经过结构筛选的字段文本 | 记录编码数、缓存命中、CPU线程、时间和内存；原文超长仍拒绝截断推断 |
| 适用性候选可能给不明确原文硬套是/否 | 明确说明、条件或矛盾由规则约束；相反类别分差不足时不给单一类别建议 | “湘西新增”“暂无业务”“是否适用”不能被模型变成适用/不适用 |

实现按“结构提取—关键差异筛选—向量候选—有来源的关系分组”执行。保留原候选导出作为兼容输出，新增集中词库核对表供开发维护，不新增单位逐条复核要求。关系不会自动成为全局别名。

先使用真实原文的代表关系和困难反例验证，再对信通、湘西209份材料复跑；另用同一批解析数据关闭模型对照，独立核算模型是否改变判断。审核意见减少、候选减少和重复关系归组分别计数，不能混为误判减少。普通办公本仍以8 GB、CPU为适配目标；本机测试不能替代Windows实机验收。
