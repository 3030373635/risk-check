# 本地语义辅助运行说明

v1.6.0 默认只使用规则和领域词库，关闭 Embedding，不加载模型。需要研究候选时，可从当前规则包创建草稿，将 `semantic_config.json` 的 `enabled` 改为 `true`，校验并指定该草稿运行；候选仍不直接决定审核通过。

可选的本地小型中文文本向量模型沿用 v1.5.0 方案。模型为 `BAAI/bge-small-zh-v1.5`，固定提交 `7999e1d3359715c523056ef9478215996d62a620`。使用 ONNX Runtime 的 CPU 后端，默认两线程、最多每批16个短文本。无需独立显卡，不启动生成式大模型，不上传审核材料。

## 资源与安装

保留项目目录结构，模型位于 `审核器/models/bge-small-zh-v1.5/`。运行依赖见 `requirements-semantic.lock`，可在安装基础审核器后安装：

```text
python -m pip install -r 审核器/requirements-semantic.lock
```

离线电脑由技术人员预先准备对应系统和 Python 版本的 wheel 文件，再使用 `--no-index --find-links <wheel目录>` 安装。模型导出所用的 torch、transformers、onnx 是开发依赖，审核运行时不需要导入它们。

`model.onnx` 和 `tokenizer.json` 约95 MB，运行会验证规则包记录的模型清单哈希及每个资源的SHA-256。只读取本地文件；缺失或损坏时明确记录未执行语义辅助，不自动联网下载。`tools/prepare_embedding.py` 仅供开发阶段重新准备固定版本模型使用，审核器不会调用它。

模型使用原版 float32，未量化。若后续采用 INT8，须重新核对向量、候选排序和完整审核结果，并发布新模型清单。

## 模型用途及判定边界

- 对规则尚未归类的适用情况原文，检索明确适用、不适用、当前无业务、模板采用/修改、权限说明和未知等类别原型。
- 载体引用核验已停止，不再检索载体候选或生成模板载体差异事项。第13条只检查删除原文，不使用文本向量。
- 对岗位对应问题，只提供同单位、业务、变体、措施编号下的部门岗位候选。先验证单位前缀，再分别计算部门和岗位向量；候选附部门列、岗位列坐标及源文件哈希。经理与副经理、不同职员等级、不同审核审批角色及明确不同部门职能的候选先排除。
- 相似度只反映模型匹配程度，不是正确概率。当前候选不自动认定等价，不自动消除审核意见，不用于第13条原文判断。
- 原文中的否定、角色、岗位层级、主体、措施编号及人员区别继续由原有规则检查。当前无业务、采用上级模板均不自动等同于控制适用或不适用。

本轮实测已出现高相似度的相反含义和不同职责。因此尚不开放“超过某个分数就自动通过”的设置。经过核对的固定关系可以按既有受控规则包流程录入相应范围的规则或别名，不能直接把候选词库转为全局白名单。

## 候选筛选参数

`semantic_config.version=2`仅允许适用性和责任主体两个领域。岗位相似度至少0.65、部门至少0.50；排序优先岗位原文一致，再按岗位70%、部门30%的组合分数排列。相近候选分差小于0.04时标注存在歧义。以上仅控制候选质量，不是通过阈值。适用性候选最低分0.70，不同含义类别分差不足0.04时不推荐；“湘西新增”、疑问、条件和复杂否定等不得借模型推定是或否。

部门职能及岗位关键差异词组在`src/risk_audit/semantic_matching.py`随代码版本冻结，筛选参数随规则包冻结。词组只用于候选排除，不是部门别名表；被排除的原文及原因仍可追溯。

## 输出及缓存

- `applicability_interpretations.json`：适用情况原文、所在行及结构化解释。
- `inventory.json`：实际选列、简称依据、错写表头原文及纠正证据。
- `semantic_diagnostics.json`：实际模型使用状态、CPU后端、编码/缓存计数、候选及运行限制。
- `semantic_relation_groups.json`、`语义关系集中核对.csv`：按同主体、业务及矩阵类型归并重复部门岗位关系，保留每个措施的矩阵和岗位清单来源。关系确认前不会自动生效，也不代替单位审核意见。
- `semantic_relation_summary.json`、`语义辅助集中说明.md`：候选、归组、拒绝推荐及排除原因统计。
- `semantic_vocabulary_candidates.json`、`语义词库候选.csv`：去重的词库候选、来源位置、限定范围和待验证关系。它们是内部开发资料，不是发给单位的新整改清单。

向量缓存保存在 `审核器/.cache/semantic.sqlite3`，以模型清单哈希和规范化原文区分。内存另缓存最多4096个向量（向量本身约8 MiB，另有索引及原文开销），跨行复用时优先查内存；磁盘缓存保留跨运行复用。重复表述只编码一次，缓存不会保存“审核通过”结论。长于512个token的输入会明确拒绝语义判断，不将截断文本当作完整原文；明确规则检查仍照常执行。

## 验收口径

8 GB 内存的 CPU 办公本为最低适配目标，16 GB 更便于同时使用 Excel。本轮实测机为 Apple M4 Max、128 GiB；模型限定为CPU两线程，但这不能代替8 GB Windows笔记本实测。完整结果见 `outputs/语义辅助验证-v1.4.0/` 中的报告。

测试已将审核运行进程的网络访问在操作系统层禁用，随后执行模型测试和完整材料审核。最终发布验证分别保存解析修复后的纯规则对照和开启语义辅助的结果，单独核算两者收益。
