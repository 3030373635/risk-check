# 审核确认稿 V1 执行口径

本版本以用户提供的《风控矩阵及三清单审核规则 审核确认稿 V1》为新的完整审核依据。源文档保存在 `规则来源/审核确认稿V1.docx`；读取以保留新增、排除修订删除后的内容为准。

## 已批准口径

- 第4条继续停用；第7条残留的第四项引用不恢复专项检查。
- 第9条检查同主体、业务及变体的当前矩阵编号与适用性；删除原文统一按第13条检查，不恢复普通载体引用核验。
- 第3条接受适用性与原因拆成两列，明确适用无需额外原因，不适用必须有原因。
- 第14条只在完整责任主体组满足列举的限定条件时判定范围；已确认普通本地组或混合组不额外强制业务适用。未知归属、来源或不完整表达保留检查限制。

## 实现变化

第5条更新部门、岗位泛称及人员完整性检查；不额外要求岗位职责编号。第6条检查有效不相容明细中的部门和岗位具体性，空清单或整行“无”“不涉及”不作为问题。

第8条编号无法关联时允许同范围控制措施有效全文的唯一精确对应；不同有效编号不因正文相同合并。第10条允许明确肯定的本岗位主体、审核或审批责任，动作、他人承担和否定不视为本岗位责任。第11条仅对明确角色验证对应责任类型；无角色由第8条提示，不重复声称独立一致性验证。

第12条排序问题写入具体相关行，有指定基准但部分编号无法定位时逐行标记待核实；第13条覆盖岗位和不相容岗位职责中同编号删除原文，找不到编号不重复提示。第14条以整组责任主体及名册完整名称判断，并将确定的外单位限定用于责任覆盖和不相容明细适用范围。第六类组合限定须同时出现省公司、物资公司。

材料类限 XLSX/XLS；说明类识别 DOC/DOCX/PDF 中明确说明或申请表述。工作簿含不同类型业务表或同表有明确业务区域时分别读取。重复内容不按多个版本计数，矩阵与三清单合并工作簿同时计入两类材料。

明确缺列写待核实意见；读取器或句式未支持的检查留内部限制，不算通过。整套材料问题在意见正文中仅使用“【第X条】”表明规则归属，问题范围在报告的“涉及位置”中显示为“整套材料”。整个包无可用表格时保存在 `runs/<run-id>/_risk_audit/待回填资料级意见.json`，不得标记写回完成。复用明确的审核意见列时先清空旧内容，再写入本轮意见；若同列在其他区域属于业务字段，则安全追加末尾列，报告布局限制，禁止覆盖原字段。整改重跑使用现行源业务数据，不继承旧副本或源材料中的历史审核意见。

## 使用

`run_audit.py` 优先使用包内源码，避免当前环境还安装旧 wheel 时执行旧算法。依赖中增加 `pypdf==6.10.2`，用于 PDF 说明识别；仍默认关闭 Embedding。

```bash
python run_audit.py --doctor
python run_audit.py config-validate risk-audit/rulepacks/releases/1.8.0
python delivery_test.py
```

本次验证使用程序构造的 Excel，不代表真实报送材料验收。原交付验证和文件校验清单记录的是原始 v1.7.0 包，新规则及程序验证结果另行保存在 `outputs/审核确认稿V1-v1.8.0/`。
