# 侧对话修复说明（1.1.1）

本版仅处理侧对话提出的第3、5、9条问题。依据新Word开展的修改已撤回，新规则更新及第13条迁移暂停；原Word文件和已有规则确认稿均未修改。程序继续采用纯代码审核，运行时不调用大模型。

## 本次处理

| 事项 | 当前执行口径 |
| --- | --- |
| 第3条：适用性及原因拆列 | 允许用“是否适用”和相邻“修改备注”等原因栏表达相同信息，不因拆列本身出意见。仍检查应保留字段、适用性填写及“不适用”原因。 |
| 第3条：原因栏读错 | 同表存在旧“修改备注”和本单位原因栏时，读取与适用性配对的原因栏。本次撤除了6条实际已填原因的错误提示。 |
| 第5条：矩阵责任主体使用泛称 | 泛称本身不构成问题。先按会计主体、业务、矩阵变体及相同控制措施编号关联岗位清单，再核对有证据支持的具体部门、岗位对应关系。未列对应控制措施的情况继续提示。 |
| 第5条：泛称、简称尚未对应 | 单独记入内部核对限制，不写成单位整改意见，也不认定已完成覆盖检查。岗位清单应填写具体部门、岗位、人员的既有要求保留。 |
| 第9条：旧载体检查 | 继续关闭旧载体、引用一致性检查。保留1.1.0的删除线原文核对：仅查相同控制措施编号对应的岗位职责，全部按原文检查，包括单字。当前仍使用第9条编号，暂不迁入第13条。 |

程序不能确定主体、业务或矩阵变体时，不跨范围匹配岗位清单，而是记录核对限制。责任主体只有部分能够对应时，继续检查可确认部分，未确认部分另行记录。

## 信通材料验证结果

本次处理10个工作簿、20张业务表、1347条解析记录。输出561条机器审核意见，合并写入405个意见单元格。对比版保留272个人工意见单元格，人工与机器意见放在表末相邻两列；没有问题的单元格留空。

另有168条覆盖关系核对限制，存于[内部核对限制](runs/sidechat-v111-verified-original/limitations.json)，没有写入单位整改意见。空白意见只表示没有可写出的材料问题，不代表全部覆盖关系已核验。

验证包括：

- 96项pytest测试通过，覆盖拆列、原因缺填、备注栏选择、具体岗位漏列、泛称映射、范围不明等情况。
- 未涉及本次调整的520条意见保持一致；第9条仍为5条删除原文问题和1条控制措施编号缺失提示。
- 使用独立的Excel XML读取校验，逐项核实本次相关的41条意见，并确认上述6处原因已填写。
- 替换633个历史人工意见单元格后，机器意见和内部核对限制均未变化；人工意见未参与算法判断。
- 251份原始材料文件哈希未变。9份原生xlsx的原业务及人工意见单元格未变；1份xls转为xlsx的审核副本，已核对8614个非空值、4878个文本单元格的删除线及3727个公式缓存值。该核对不代表原xls的全部公式表达式、字体样式和嵌入对象均已验证。

意见数量减少不能直接换算为准确率。当前仍需人工确认部分泛称和简称与实际岗位的对应关系。
